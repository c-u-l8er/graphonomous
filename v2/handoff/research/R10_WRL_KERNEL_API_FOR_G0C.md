## 2. The exact `rev-` byte rule

```
rev = canonicalizeRelationRevision(input)             // relation-identity.js:672-689
bytes = W.serializeArtifact(rev)                       // wrl.js:1213-1215 → canonicalJson :1196-1210
rev-id = "rev-" + sha256Hex(bytes)                     // relation-identity.js:693-694
```
`canonicalJson` (`wrl.js:1196-1210`, quoted): BigInt → `value.toString()`; arrays → `"[" + map(canonicalJson).join(",") + "]"`; objects → `"{" + Object.keys(value).sort().map(k => JSON.stringify(k) + ":" + canonicalJson(value[k])).join(",") + "}"`; `typeof value === "number" && !Number.isSafeInteger(value) && Number.isFinite(value)` → `fail("WRL_NUMERIC_RANGE", …bounded to +/-9007199254740991)`; everything else `JSON.stringify(value)`. Consequences, all probed: **hashed** = exactly the seven `REVISION_FIELDS` present in the input (an absent `texture` is absent from the bytes; `texture: undefined` *with the key present* is refused `WRL_BAD_RELATION_REVISION` at :619-623, so omit the key); **excluded** = nothing is silently dropped — any eighth field is `WRL_BAD_RELATION_REVISION unknown field(s)` (:540-544), so `provenance`, `relation_id`, `revision_id`, `world_id`, `assertions` cannot ride in a revision. **Attributes**: any nesting accepted (`{loc:{file,line}, tags:[…], ok:true, n:null}` → ACCEPTED); float `0.5` and `2^53` → `WRL_NUMERIC_RANGE`; BigInt `2^64` accepted (diverges from RFC 8785 — R5 §3.3); `{w: undefined}` produces **invalid bytes `{"w":undefined}` with no throw**, `NaN` → `null`, non-ASCII passes literally — pre-validate to spec §6.2 before calling. **`policy`**: checked only as a non-empty string (:546-551), any value hashed (`"anything.at.all"` ACCEPTED; a different policy moves `rev-`); never compared to a rulepack — that is GAP-W9 / D-018.
Kernel bytes for the §5 example: `{"attributes":{},"domain":"semantic","endpoints":[{"role":"source","terminal":{"object_id":"receipt_sha256_abc","port":"node"}},{"role":"target","terminal":{"object_id":"claim_crosswalk_E_48","port":"node"}}],"kind":"WITNESSES","orientation":"directed","policy":"graphonomous.semantic.rules.v0","texture":"solid"}`.

## 3. The exact `rel-` rule

An **allocation** is a tagged record of one of three variants (:699-716; spec D8.1 `spec.html:1655-1700`: `relation_id = H("WRL_RELATION" ‖ "named-initial" ‖ world_id ‖ relation_name)`). The kernel realises `‖` as key-sorted JSON, not concatenation (:888-897): preimage = `W.serializeArtifact({tag:"WRL_RELATION", variant, world_id, relation_name})` → `{"relation_name":…,"tag":"WRL_RELATION","variant":"named-initial","world_id":…}` (probe-confirmed; manual sha256 of that string equals the kernel's `rel-`). **`named-initial`** = `{world_id, relation_name}`, the only variant an author may mint (:753, :797-808); `relation_name` is any non-empty string to the kernel (`"a:b/c%d?e"` ACCEPTED at :847-849) — only relation-v2's *surface* narrows it to `RELATION_NAME_RE=/^[A-Za-z_]\w*$/` (`relation-v2.js:1432, 1450-1460`, `WRL_BAD_RELATION_NAME`), which G0 does not go through. **World-scoped (D8.5, `spec.html:2412-2450`)**: `world_id` is in the preimage, so the same name in two worlds mints two `rel-` (probe: `false` for equality; law `relation/world-scoping/a-named-allocation-is-world-scoped`, `test/conformance.mjs:2495-2504`), and any re-seal moves every `rel-` while `rev-` holds. In V2 the world id enters via `expandSeed(worldId, seed)` (`relation-v2.js:714-719`) after `worldId = "sem-" + sha256(serializeV2Artifact)` (:752), and the seed stored in the artifact carries **no** `world_id` (:289-294, `WRL_BAD_IDENTITY_SEED`). **Hard fact for G0-C: `validateAllocation` refuses any `world_id` not matching `/^sem-[0-9a-f]{64}$/`** (:851-854) — `namedInitialAllocation("gsem-…")`, `relationIdFromAllocation({…world_id:"gsem-…"})` and `V2.expandSeed("gsem-…")` all throw `WRL_BAD_ALLOCATION | world_id | world_id must be a sem- id` (probe). So the kernel cannot mint a `rel-` scoped to a `gsem-`; see §7.

## 4. How a world's `sem-` is computed today, and what makes `gsem-` differ

V1: `sealWorld` (`wrl.js:1277-1300`): `artifact = graphToIr(canonicalizeGraph(parseWrlCore(desugared)))`; `bytes = serializeArtifact(artifact)`; `semanticId = "sem-" + sha256Hex(bytes)` (:1285-1286; also `semanticArtifactId` :1231-1233). V2: `v2WorldIdOfArtifact(a) = "sem-" + sha256Hex(serializeV2Artifact(a))` (`relation-v2.js:733-735`), `serializeV2Artifact = W.serializeArtifact(canonicalizeV2Artifact(a))` (:681-683). `canonicalizeV2Artifact` (:648-678): (1) `assertV2Artifact` — tuple gate `(ir_version "2.0", profile_id, semantic_policies.rulepack_id)` against `V2_RELATION_SOURCE_FAMILIES` (:177-182, :437-461), refuses `edges` (:466-473), requires `V2_REQUIRED_KEYS=["ir_version","profile_id","semantic_policies","objects","relations"]` (:417-419), then `assertV2World` (:589-623) which *derives* a V1 world through `projectRelationRevisionToV1Edge` + `graphToIr` (:536-568) and demands the stated `semantic_policies` and `schemas` equal the derived ones (`V2_DERIVED_KEYS` :579) and the stated objects equal the derived bag (ports/`state_schema_ref` are functions of role, :605-620); (2) `relations.map(canonicalizeV2Relation)` = `{identity_seed: canonicalizeSeed, revision: R.canonicalizeRelationRevision}` (:406-412); (3) duplicate seed → `WRL_DUPLICATE_RELATION_SEED` (:658-669); (4) relations sorted by `serializeArtifact(identity_seed)` (:671-675); (5) objects replaced by the derived (V1 identity-first `(object_id, role)`) order (:677). Artifact object = `{ir_version, profile_id, semantic_policies:{rulepack_id, numeric_policy_ids, admit_policy_id, film_schema_id}, schemas:{…}, objects:[{object_id, role, static_config, state_schema_ref, ports}], relations:[{identity_seed, revision}]}` (R5 §2.3 bytes).
**A G0 world dies at step (1)**: `assertV2Artifact/canonicalizeV2Artifact/v2WorldIdOfArtifact/deriveV2Relations` all → `WRL_UNSUPPORTED_PROFILE | profile_id` (probe); with `profile_id` forged to forge it dies one gate later, `WRL_UNSUPPORTED_FEATURE | kind | relation kind 'WITNESSES' has no V1 edge form`. So G0-C must own steps (2)-(5) itself (relation layer reusable: `V2.canonicalizeV2Relation` ACCEPTS a G0 relation) and hash with `W.serializeArtifact` + SHA-256, prefix `gsem-`. **What would make `gsem-` bytes ≠ a future real `sem-`**: the envelope. A WRL static profile (D-017) will still emit whatever `graphToIr`-shaped derived fields it defines (`schemas`, per-object `state_schema_ref`/`ports`, the full `semantic_policies` tuple), and G0's envelope has none of those decided — so expect the bytes to differ, which is exactly why D-017 forbids renaming `gsem-`→`sem-` and requires a new seal plus recorded equivalence. Identical bytes are possible only if G0 emits the envelope the future profile derives, byte for byte.

## 6. What the kernel refuses that G0 will meet (all probed)

- **Roles**: only `source|target|peer|terminal` (:579-582) — `role "asserts"` → `WRL_ENDPOINT_ROLE_ILLEGAL`; `peer` inside `directed` → same code (:583-587). G0's §3.2 roles are exactly `source`/`target`: fine. Two sources + one target ACCEPTED (n-ary); two sources, no target → `WRL_INCOMPLETE_ORIENTATION`.
- **object_id / port**: `/^\w+$/` (:384, :399-403). `:` `/` `%` `-` `é` all → `WRL_BAD_TERMINAL`; `__` accepted; empty port refused; a packed `"a.node"` string refused. **Every G0 lid (`[A-Za-z0-9._:/@+-]`, spec §4.1) is refused as an `object_id`** — G0-C must define a reversible `lid → \w+` encoding for terminals (and keep the real lid in `static_config` or its own record); the encoding is hashed into every `rev-`, so freeze it in the profile.
- **Endpoint order**: never required — the kernel sorts (array reversed → same `rev-`; roles swapped → different `rev-`). **Terminal uniqueness** per relation, not per role (:590-605): `WRL_DUPLICATE_TERMINAL`; a self-loop needs two distinct ports on one object (ACCEPTED with `node`/`node2`).
- **Attributes**: must be a record (`[]`/missing → `WRL_BAD_RELATION_REVISION`); `{}` accepted and **emitted** (`"attributes":{}` is in the bytes; V2 does not elide it). Floats → `WRL_NUMERIC_RANGE`.
- **Policy**: unknown string accepted and hashed (GAP-W9).
- **Texture**: directed without `texture` → `WRL_MISSING_TEXTURE`; `"weak"` → `WRL_BAD_RELATION_REVISION`; `async` accepted; acausal + texture → `WRL_ACAUSAL_TEXTURE`. **Orientation** `"undirected"` refused. `domain`/`kind` any non-empty string (`"semantic.WITNESSES"` accepted).
- **D8.3 provenance**: `provenance` key → `WRL_BAD_RELATION_REVISION unknown field(s) provenance` (:540-544); the seven backpointer names → `WRL_REVISION_BACKPOINTER` (:531-538). Provenance lives on G0's assertion records (spec §4.4), keyed by `rel-`/`rev-`.
- **Allocation**: extra field / unknown variant / empty name → `WRL_BAD_ALLOCATION`; `named-initial` passes `assertAuthorableAllocation` and fails `assertImportableAllocation` (`WRL_UNWRITABLE_ALLOCATION`); **`gsem-` world_id → `WRL_BAD_ALLOCATION`** (:851-854).

## 7. What G0-C must / must not do (D-009, D-017, D-018, spec §7, this map)

1. **World id is `gsem-` + sha256(`W.serializeArtifact` bytes), never `sem-`** (D-009; §7.2). Never rename `gsem-`→`sem-`; when WRL seals the same artifact, record a new `sem-` plus explicit supersession/equivalence (D-017). Do not call `v2WorldIdOfArtifact`/`canonicalizeV2Artifact` — they refuse the profile (§4).
2. **`rev-`: call the kernel** — `relationRevisionId(rev)` over `{domain:"semantic", kind, orientation:"directed", texture:"solid", endpoints[{role, terminal:{object_id, port:"node"}}], attributes, policy:"graphonomous.semantic.rules.v0"}` (§7.2). Omit `texture` only for non-directed kinds (none at G0). Pre-validate attribute values to spec §6.2 (no floats/`undefined`/NaN/non-ASCII) because the serializer is silent on three of them.
3. **`rel-`: the kernel cannot scope to `gsem-`** (`validateAllocation` :851-854). Two lawful options, to be ruled and logged: (a) G0 computes `"rel-" + sha256(W.serializeArtifact({tag:"WRL_RELATION", variant:"named-initial", world_id:<gsem->, relation_name}))` — the D8.1 preimage with a G0-owned scope, kernel-verified for the `sem-` case (§5 step 3, `true`), labelled as the adapter; or (b) propose widening `:851` to `/^g?sem-…/` to the WRL owner alongside D-017. Option (a) is what `WRL_SCHEMA_OR_PROFILE/README.md` already assumes ("with the `gsem-` as `world_id`") but it is **not** "minted by the kernel" — say so in the receipt. Never pass a `sem-` you did not get from WRL as `world_id` (forged spine identity, D-009 alt. c).
4. **Relation names**: `relation_name` = the statement lid (`rel:<kind>:<src lid>:<tgt lid>`, spec §4.3) is accepted by the kernel's allocation and by `V2.validateIdentitySeed`, but not by the V2 *surface* (`RELATION_NAME_RE`); the sandbox text surface (§7.6) is G0's own reader, so this is fine — do not run names through `namedInitialSeed`.
5. **Terminals**: one nominal port `node` per object (GAP-W7 adapter); `object_id` must be `\w+` — freeze a reversible lid encoding in the profile data; the raw lid stays in `static_config`.
6. **Canonicalization G0 owns** (mirror `relation-v2.js:648-678`): per-relation `V2.canonicalizeV2Relation`; refuse duplicate seeds; sort relations by `serializeArtifact(identity_seed)`; sort objects identity-first `(object_id, role)`; no stored `relation_id`/`revision_id`/`world_id` anywhere in the artifact (`DERIVED_NEVER_STORED`, `relation-v2.js:366-370`; seed `world_id` refused :289-294). **No coordinates, snapshots, timestamps or provenance in identity** — those are assertion/event data (D8.3; spec §7.4, §4.4).
7. **Profile as data**: author `WRL_SCHEMA_OR_PROFILE/graphonomous.semantic.v0.json` in the §D6.1 eight-item shape plus role declarations (`spec.html:1219-1245`; GAP-W1 spec-text hole), enforced by G0's validator; `revision.policy` is the constant `graphonomous.semantic.rules.v0` and never an attribute slot (R5 G9).
8. **Claims**: G0-C may claim "kernel-native `rev-`" and "D8-shaped world". It **must not** claim "WRL-sealed" or "seal-native" until (i) D-017's gates pass and (ii) GAP-W9 is repaired (`policy` validated against the profile's declared vocabulary) — D-018 makes W9 blocking for exactly that claim.
