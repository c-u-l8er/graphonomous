# G0.5-R1 / R2 — clean-checkout reproducibility closure

**Ruling:** GPT Adjudication v6 §7 → **D-069**.
**Kind:** Graphonomous test/handoff work. **Not** a stack repair — no `STACK_FIX_RECEIPTS/` entry, no owning-layer
change, no TRVM/WRL commit.
**Date:** 2026-09-03. **Tree:** `graphonomous/v2`.

## The defect, as GPT measured it

Running the extracted handoff ZIP:

```
node --test test/g05.test.mjs        →  8 pass · 2 fail
node tools/g05_build.mjs --out ui/data
node --test test/g05.test.mjs        → 10 pass · 0 fail   (37,427,667 bytes across four world payloads)
```

Both failures came from one cause: `ui/data` is a 36 MB build product, gitignored and excluded from the ZIP **on
purpose** (`tools/make_gpt_bundle.mjs` skips it explicitly), and the test file required it to already exist —
(1) directly, as an assertion, and (2) indirectly, because the static-server test served `ui/` and then fetched
`data/index.json`, which 404s when `ui/data` is absent.

Separately, `test/projection.test.mjs` called `project()` **at module top level**, so in a tree without the pinned
source registries the file threw during import and the whole file went red. A clean verification bundle looked broken
for doing exactly what it was designed to do.

## R1 — the payload is built into a temp fixture, and `ui/data` is only a staleness check

`test/g05.test.mjs` now shapes its temp directory as a **complete `ui/` fixture**: the three shipped page files copied
beside a freshly generated `data/`.

```js
const FIXTURE = mkdtempSync(join(tmpdir(), "g05-"));
const OUT = join(FIXTURE, "data");
for (const f of ["index.html", "app.js", "app.css"]) copyFileSync(join(V, "ui", f), join(FIXTURE, f));
execFileSync(node, [tools/g05_build.mjs, "--out", OUT]);
```

- the server test serves `FIXTURE`, not `ui/`, so `data/index.json` exists by construction;
- determinism is measured as before, by building a **second** temp copy and comparing byte-for-byte — that test no
  longer mentions `ui/data` at all;
- the comparison against the developer's `ui/data` became its own test that **skips with the build command** when the
  directory is absent. It is a staleness check for a working tree, never a correctness gate.

**Measured, with `ui/data` moved out of the tree:**

```
$ test -d ui/data && echo yes || echo no
no
$ node --test test/g05.test.mjs
ℹ tests 11 · pass 10 · fail 0 · skipped 1
```

and with it present: `11 tests · 11 pass · 0 fail · 0 skipped`. The skipped one is the staleness check, by design.

## R2 — one documented target, green from the bundle, and skips that say why

`test/helpers/sources.mjs` asks git once per snapshot whether each pinned source commit is present, and returns a
reason naming the first missing pin. `test/projection.test.mjs` probes before it builds, catches a failed rebuild, and
every one of its 18 tests now calls `unavailable(t)` first — so the file **skips with a reason** instead of throwing at
import. `test/certificate.test.mjs` and `test/factory.test.mjs` already did this; they were the model.

`tools/test_repro.mjs` is the documented target, and it takes both roles from **one file list** so the clean target
cannot rot by someone forgetting to add a new test file to it:

| command | what it asserts |
|---|---|
| `npm run test:repro` | every test file ran and **nothing failed**; the Python canonicalizer twin self-tests; each of the four shipped projections passes `verify`, `verify-eval` and `check-cert`. Skips are allowed **and every skip is printed with its reason.** |
| `npm run test:full-tree` | all of the above, **plus** the pinned registries are reachable — so a skip can never hide a regression in the real checkout. |

`npm run build:ui` and `npm run ui` are the two other things a reader needs and had to find in a comment before.

## What was NOT done, and why

- **The 36 MB build product was not committed.** D-069 forbids it explicitly, and it would put a generated artifact
  under version control to make a test pass.
- **`ui/data` was not added to the ZIP.** Same reason; the receiver rebuilds it with `npm run build:ui`, and the test
  file rebuilds it into a temp directory regardless.
- **No test was deleted or weakened to get green.** The determinism check got *stronger* (it now also compares the
  emitted file-name sets); the `ui/data` comparison was moved, not dropped.
